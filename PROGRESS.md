## Ideas

- If the single-question answers stay uninformative, ask *what to build next* rather than *what to pay for* (multi-select: community animation library / rule backup / time profiles): a feature vote is answerable by people who would never pay, and the monetization read can come from `support_clicked` instead.

- The question is only asked with statistics on, so users who declined are never asked (accepted, because an answer that cannot be recorded is not worth asking for). Read the distribution as a share of consenting users, never as a count. **Testimonial against that decision (2026-10-14):** the owner went looking for the card on the device and reported it missing ("je ne retrouve plus le form (don, mensuel, …) qui est utile pour les datas") — statistics were simply off, so the card was hidden as designed. The gate is honest for the data and invisible to the user; making the card visible with a line saying where to turn statistics on is the cheap alternative if a second person trips on it.
- Push a bootstrap nudge for the first telemetry release (pinned GitHub discussion + release notes), since v0.6.0 is the first version able to report anything.
- Consider enabling R8 for release builds: the analytics SDK costs ~900 KB unminified, R8 would shrink that and the rest of the app.
- Self-hosted alternative (Cloudflare Worker + D1) if the PostHog free tier or third-party hosting becomes a constraint.
- Track the analytics opt-in rate as a dashboard insight: a rate below ~10 % makes the sample unrepresentative.
